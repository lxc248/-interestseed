## 4. 对比

### 学生

```text
1.8.0：4,432ms，7 步，完成核心判断
2.3.1：8,370ms，8 步，完成核心判断 + 来源回跳 + 时间线 + 路线
```

2.3.1 多出的不是主流程摩擦，而是三项新的可选验证：

- 来源可点击；
- 观察时间线；
- 可读路线。

### 上班族

```text
1.8.0：4,350ms，7 步，完成专注判断
2.3.1：7,815ms，7 步，完成专注判断 + 时间线 + 路线
```

判断步骤没有变多；增加的是“记录后能回看什么”。

## 5. 结论：取哪个

### 最优产品组合

```text
2.3.1 的数据层
+ 1.8 / 2.1 的主界面层级
+ 默认不自动生成路线
```

理由：

1. 两轮 2.3.1 都完成，错误为 0；
2. 来源回跳、时间线、路线都成功；
3. 主界面仍只有 `记录 / 收件箱 / 更多`，没有因为新能力增加按钮；
4. 兴趣路线只在用户显式执行时生成，不会变成自动写文件；
5. 1.8 更快，但缺少“为什么留下”的证据；2.3.1 更完整，且没有牺牲核心路径。

### 不选

```text
1.8.0 单独作为最终版本
```

它能更快完成判断，但用户之后无法回答：

- 这条兴趣从哪里来？
- 上次判断是什么？
- 现在是否还成立？

```text
2.3.1 全自动路线
```

路线不应在每次打开时自动生成。  
本轮已验证：显式生成足够，自动生成只会增加写入和噪音。
