# InterestSeed 1.8.0 — 两个身份的真实 UI 任务测试

> 说明：这是在真实 Obsidian UI 中执行的角色化任务测试，不是手写虚构日志。  
> 所有点击、弹窗、状态变化和截图都来自 Obsidian CDP；两个身份各用一套任务脚本。  
> 不是外部真人受试者，因此不把小样本自动化耗时当作大规模用户研究结论。

## 测试环境

```text
Obsidian 1.14.5
Disposable vault: InterestSeed-4C11-Disposable
插件版本: 1.8.0
视口: 2560 × 1536
```

## 身份 A：大三视觉设计学生

角色设定：

```text
非技术背景
每天刷小红书 / 抖音找灵感
用 Obsidian 记课程笔记
收藏很多，但很少回看
```

任务：

1. 打开冷启动问卷；
2. 不完成四问，直接走“先跳过，记录一条”；
3. 加入一条设计分享；
4. 从标准列表进入判断；
5. 只是路过，不写图谱；
6. 打开 3/7 天验证行动；
7. 点一下“做了”；
8. 撤销，确认没有测试脏数据。

实际结果：

```text
sparkOpen: 1
sparkHasText: true
pendingAfterPass: 0
beforeLogs: 0
afterLogs: 1
restoredLogs: 0
totalMs: 4433
```

关键发现：

- 跳过按钮在旧样式下几乎不可见；
- 修复后，“先跳过，记录一条”成为清晰第二行动；
- 学生不必先完成四问，也能直接进入真实记录；
- 标准列表让他们先看到可处理的条目，不需要先学 Focus Deck。

## 身份 B：工作 2–3 年的产品/运营上班族

角色设定：

```text
下班后只有 15 分钟
刷抖音 / 小红书收集增长和汇报内容
不想填长表
希望先看到清单，再决定是否专注
```

任务：

1. 放入两条工作相关分享；
2. 默认看到标准列表；
3. 点“专注一条”；
4. 左滑 / 键盘左箭头路过；
5. 返回列表；
6. 打开一条判断卡；
7. 打开验证行动；
8. 点“只想过”；
9. 撤销，清理队列。

实际结果：

```text
pendingAfterSwipe: 1
beforeLogs: 0
afterLogs: 1
restoredLogs: 0
totalMs: 4350
```

关键发现：

- 上班族默认看到列表，知道“现在要处理什么”；
- 想快速处理时才进入 Focus Deck；
- “返回列表”保证不会被困在单一交互；
- 一键“只想过”比填写三组量表更符合下班后的精力。

## 与之前版本比较

| 项目 | 之前 | 1.8.0 |
| --- | --- | --- |
| 新实验长度 | 7 天 | 3 天，可延长到 7 天 |
| 每日记录 | 兴趣 1–5 + 精力 1–5 + 证据 | 一次点击：做了 / 只想过 / 没做 |
| 跳过冷启动 | 进入空白图谱 | 直接进入记录一条 |
| 收件箱默认 | Focus Deck 卡片 | 标准列表，Focus Deck 可选 |
| 命令入口 | 工具栏为主 | 工具栏 + 命令面板 + 快捷键 |
| 总览/探索 | 亮色弹窗 | 深色统一界面 |

## 结论

两个身份都完成了核心任务，没有出现：

- 丢失数据；
- 无法返回；
- 必须学习滑动手势；
- 必须填写长表；
- 测试数据残留。

仍需继续观察：

- 3 天试跑完成后的延长决策；
- 移动端软键盘与列表滚动；
- 大规模真实用户对 Focus Deck 的偏好比例。
