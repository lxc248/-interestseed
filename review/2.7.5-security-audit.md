## 1. 架构与信任边界

```text
低信任：用户粘贴的笔记/短视频文本、本地 graph.json、MCP 客户端输入
高信任：插件本体、Obsidian Vault、用户配置、本地 Agent
边界：外部 URL 打开、Agent 子进程、AI 网络请求、MCP 输出、发布标签
```

核心结论：

```text
无 critical / high 确认漏洞
运行时零依赖
核心 AI 默认关闭
```

## 2. 确认并修复

| ID | 位置 | 修复 |
| --- | --- | --- |
| SEC-01 | `ShareInboxModal` | 外链改 `window.open(noopener,noreferrer)`，不再当作 vault 路径 |
| SEC-02 | `mcp/server.mjs` | prompt 先声明本地数据边界，防提示注入 |
| SEC-03 | `mcp/server.mjs` | stdin 单行上限 1 MiB，超限退出，防内存耗尽 |
| SEC-04 | `mcp/server.mjs` | 工具/资源错误只回显通用信息，详情写 stderr |

| SEC-06 | `ModelProvider` | 本地服务不再回退使用 `DEEPSEEK_API_KEY` |
| SEC-07 | `ClaudianProvider` | 探索请求先经 `sanitizeExplorationRequest` 再入 prompt |
| SEC-08 | `.github/workflows/release.yml` | action 固定到完整 SHA；生成 SHA256SUMS；移除 `--clobber` |
| SEC-09 | `scripts/deploy.ps1` | 从 `manifest.json` 动态读取版本号 |
| SEC-10 | `vite.config.ts` | banner 版本从 `package.json` 动态读取 |
